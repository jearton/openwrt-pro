## 拟执行的隔离方案

1. 只对 9000 和 9001 操作。先保存 VM 配置和非目标对象摘要，正常关闭 9000，将当前系统盘冷复制为新的工作磁盘；保留磁盘 16 不写入，在工作副本启动测试。该步骤会短时中断实验路由器的管理与 DNS。
2. 启动 9001。模拟 WAN、bond、WireGuard 对端和测试 VLAN 均限定在两台 guest 及它们的临时 namespace；不增加物理桥成员、不修改 PVE 生产路由、交换机或生产 DNS。
3. 保持 IPv6 禁用。OpenClash 只对实验客户端及测试目标生效，使用先前授权的测试节点；代理凭证只保存在受控临时文件，不进入 Git、截图、日志或镜像。
4. 逐项创建前读取配置、保存回滚点，配置后回读并执行实际业务请求及计数检查。Technitium 只通过正式 API 修改，配置文件不能绕过运行中服务直接覆盖。
5. 每项记录通过、失败、部分验证或未验证及证据。遇到管理链路丢失、主 DNS 错误、隔离破坏或非目标配置变化，停止并立即回滚；不能以重试成功掩盖首次失败。
6. 测试结束正常关闭工作副本，重新挂回原磁盘 16，并核验原有服务、DNS、IPv6 和隔离状态；9001 恢复关机。临时接口、密钥、配置和控制端按任务清单清理，失败工作盘保留作为排障证据。

## 授权边界

新的多 WAN、VPN、限速、虚拟磁盘及服务变更需要当前方案的明确 ok。原有批准仅沿用到同一已授权操作，不能扩大为生产网络或控制面变更。Tailscale 若需端到端验收，先准备独立控制面方案；本轮不更改现有 Headscale ACL、生产节点或 subnet routes。固件有缺陷时保留复现证据，不覆盖已发布 Release 附件。
